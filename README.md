# Rust Documentation MCP Server

> **Supercharge your AI Editor with Rust Superpowers.** 🚀

The `mcp_rustools` server connects your LLM (Trae, Cursor, Claude) directly to the Rust ecosystem (`docs.rs`, `crates.io`, `rust-lang.org`), enabling it to fetch accurate documentation, explain concepts, and fix errors in real-time.

## ✨ Key Features

- **Context Bundles**: Get a complete crate overview (README + Modules + Features) in a *single* tool call.
- **Smart Discovery**: Find crates by name or function signature (`fn(u32) -> String`).
- **Deep Code Access**: Read actual source code when documentation is insufficient.
- **Macro Vision**: Expand macros (`#[tokio::main]`) to see the actual code generated by the compiler.
- **Error Intelligence**: Explain compiler errors (`E0382`) with official Rust Book context.
- **Offline-First Speed**: Persistent caching means instant responses for frequently used docs.

## 📦 Installation

### Option 1: Build from Source (Recommended)

1.  **Clone the repo**:
    ```bash
    git clone https://github.com/zakarialabib/rustools-mcp.git
    cd rustools-mcp
    ```
2.  **Build**:
    ```bash
    cargo build --release
    ```

### Option 2: Run Directly
You can point your MCP client directly to `cargo run`.

## 🔌 Configuration

### Trae / Cursor (Stdio Mode)

**Stdio mode is strictly recommended** to avoid CORS and network issues.

Add this to your `mcp_config.json` (or equivalent):

```json
{
  "mcpServers": {
    "rust-docs": {
      "command": "cargo",
      "args": [
        "run",
        "--release",
        "--manifest-path",
        "C:/absolute/path/to/rustools-mcp/Cargo.toml",
        "--",
        "stdio"
      ]
    }
  }
}
```

> **Note**: Replace `C:/absolute/path/to/...` with the actual path on your machine.

### HTTP / SSE Mode (Advanced)

If your client supports Server-Sent Events (SSE) or runs remotely, you can use the HTTP mode.

**Command:**
```bash
cargo run --release -- http --address 127.0.0.1:8080
```

**MCP Configuration:**
```json
{
  "mcpServers": {
    "rust-docs": {
      "url": "http://127.0.0.1:8080/sse"
    }
  }
}
```
> **Note**: You must start the server manually in a terminal before connecting your client.

## 🧭 The "Holy Trinity" Workflow

Teach your AI to use this workflow for best results:

| Step | Goal | Tool |
| :--- | :--- | :--- |
| **1. Discovery** | Find the right crate. | `find_crates("async http")` |
| **2. Analysis** | Load the map. | `get_context_bundle("reqwest")` |
| **3. Validation** | Get the details. | `get_symbol_docs("reqwest::Client")` |

## 🛠️ Available Tools

| Tool | Description |
| :--- | :--- |
| `get_context_bundle` | **Start here.** Fetches README, Features, and Dependencies. |
| `get_crate_modules` | Lists the public API surface (structs, enums, mods). |
| `get_symbol_docs` | Gets detailed docs for a specific item (`std::vec::Vec`). |
| `read_source_file` | Reads the raw source code of a file. |
| `expand_macro` | Expands macros to show generated code. |
| `analyze_feature_flags` | Explains `cfg(feature = "...")` flags. |
| `explain_error_code` | Explains `E0xxx` compiler errors. |
| `get_language_concept` | Explains concepts like "ownership" or "lifetimes". |
| `find_crates` | Searches crates.io. |
| `find_by_signature` | Finds functions by type signature. |

## ❓ Troubleshooting

### "Tool returned null"
- This usually means the crate or version wasn't found, or the documentation format was unexpected.
- **Fix**: Try `find_crates` to verify the name. Try `get_crate_modules` to see valid paths.

### "Connection Refused" (SSE)
- Ensure the server is running (`cargo run --release -- http`).
- Local web clients (like some browser-based editors) often block local HTTP connections.
- **Fix**: Switch to **Stdio** mode configuration above.

### "Access Denied" (Windows)
- The binary might be locked by another process.
- **Fix**: Stop the MCP server in your editor or run `cargo clean` if stuck.
